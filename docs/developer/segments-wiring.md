# Root integration checklist for issue 6

Only the Query and Segment modules and their focused tests are implemented here. Root owns shared file integration.

1. In `Model/ColumnDefinition::assertOperators`, replace the static operator membership check with `MetadataCondition::operators($this->source, $this->type)`. Import that class. Keep duplicate detection, opt-in filtering, source rules and native exact-only behavior. Do not enable all operators by default. Add shared model tests for type/source rejection and enabled number/date ranges.
2. Add labels and upper-bound controls to the existing filter UI for enabled operators. The range request uses `nat_filter_to_COLUMN`. Unknown operator values remain fail-closed. Use the same matrix to limit choices. Do not advertise relative dates or relationship operators.
3. Resolve and authorize the visible view with the view module, then construct `SegmentRepository($postType, $viewId)`. `default` is the base configured view ID. Do not trust the raw active-view user option without checking visibility. Personal segment options and shared options are independent. The repository never reads request user IDs.
4. Add authenticated, nonce-protected save/delete/default endpoints and controls. Store through `SegmentDefinition`. Render labels with escaping. Revalidate through `SegmentRequest::compile` before saving if the UI should reject stale configuration immediately; replay always revalidates. The repository itself enforces edit capability and shared administrator permission.
5. Select the requested segment or scoped default before calling `applySegment`. Do not run the legacy browser filter hook as an additional second pass on a segment request. Clear/reset must explicitly suppress defaults. Explicit browser filters/sort/search/status should suppress automatic defaults as a whole. Define and test personal versus shared default precedence; the module deliberately has no implicit precedence.
6. Hydration failure or invalid default reference must show an error and force an empty result, rather than silently ignore filters. Catch `InvalidArgumentException` at hydration. The controller handles replay validation failures. Preserve pagination and never set unbounded `posts_per_page`.
7. Run existing real WordPress query regressions plus added browser/operator/segment permission and 10,000-record cases. Stable ID tie-breaking changes `orderby` from a string to a WordPress order map; update assertions that compare its representation, while preserving result-order assertions.

The module leaves metadata/ACF duplicate-free grouping and missing-row inclusion to existing WordPress query behavior. Core NULL ordering remains direction-dependent. No universal missing-last policy or performance result is claimed.
